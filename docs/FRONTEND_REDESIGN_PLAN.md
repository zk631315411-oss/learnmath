# LearnMath 前端重构计划（v2 · 已定稿）

> 背景：现有前端不是"丑"，是三个结构性问题——对话与书页脱节、学习地图被埋、移动端是阉割版。
> 本计划以「页面为锚的学习空间」为目标重构交互模型，技术栈不变（React + Tailwind）；不改现有问答/SSE/evidence/learning-map API，仅新增一个教材章节页码的只读查询接口。

## 一、现状问题（重构的靶子）

| # | 问题 | 现状 | 后果 |
|---|------|------|------|
| 1 | 对话与页面脱节 | 右栏是全局单线程聊天，翻页对话不变 | 「来源提问」按钮本质是事后缝补 |
| 2 | 学习地图被埋 | Phase 2 核心产出藏在 260px 侧栏 tab 里 | 激励与复盘价值全丢 |
| 3 | 移动端阉割版 | AiBall 悬浮球妥协：挡内容、拖拽定位状态、展开盖半屏 | 体验破碎，维护两套交互 |
| 4 | 视觉无锚点 | 主色亮蓝 SaaS 感、圆角/投影不统一、元素间距无节奏 | 观感"不精致"的直接来源 |

## 二、目标形态

### 2.1 信息架构：两个模式，一条主线

```
┌─────────────┐    点章节卡/继续学习    ┌─────────────┐
│  地图模式    │ ──────────────────────▶ │  阅读模式    │
│  (默认首页)  │ ◀────────────────────── │  (沉浸式)    │
└─────────────┘    顶栏「地图」随时回     └─────────────┘
```

- **地图模式** = 首页 + 复盘页：「继续学习」卡、章节卡片网格、需要巩固列表
- **阅读模式** = PDF 阅读区 + 右侧旁批面板；提问记录和学习地图通过 PDF toolbar 打开的覆盖式 drawer 访问（见 2.3）
- 不引 react-router，用 App 顶层一个 `view: 'map' | 'reader'` 状态切换（应用只有两屏，路由是过度工程）

```

**启动策略（已定）**：**首次进地图，之后恢复 PDF**——**按教材隔离**。
- 判定：该教材无证据（chapters 接口 explored=0）或该教材无 workspace 记录 → 地图模式；否则恢复该教材上次的阅读模式+页码。
- workspace 记录按教材存：`learnmath.workspace.<textbookId>` = `{ view, page, updatedAt }`——否则在甲书进过 PDF 后，首次打开乙书会被错误地直跳 reader（乙书其实零上下文）。
- 「直接开始阅读」逃生口常驻地图模式顶部。

**数据来源与加载策略**（复用现有接口 + §2.2 一个新增只读接口）：

| 区块 | 来源 | 说明 |
|---|---|---|
| 章节卡片（状态条/探索进度） | `GET /api/learning-map/chapters` | 已有：每章 status_counts + exploration_progress |
| 「继续学习」卡 | `chapters` 找 needs_review/learning 章 → `GET /nodes?chapter=` 取章节顺序首个 learning/needs_review 节点 | 节点上的 `chat.id` → `chat_history.page_number` 得落地页码 |
| 需要巩固列表 | 同上，`/nodes` 过滤 needs_review | 现 ChapterMapView 同款数据 |
| 章节卡落地页码 | 见 D1（方案 A 扫描接口 or 方案 B evidence） | 唯一后端增量 |

**地图首页加载策略（已定，选第一种）**：进入地图时**并发加载所有章节节点**（4 本教材章节数 ≤12，并发量可控），章节卡区域先显示骨架屏。
- 单章失败不阻塞其他章节（该章卡显示"加载失败 · 重试"），整页不白屏。
- 结果做 **session 级缓存**（内存 Map，切章/切教材失效，不持久化）——地图页内反复进出不重拉。
- 不新增聚合接口：并发 /nodes 已够用，聚合接口等真出现性能问题再说。

**章节首页落地（D1 详案）**：
- 手工「章节→页码」映射表**否决**：4 本书的静态表会随教材更换腐烂，且章节名带 LaTeX 噪声，匹配脆弱。
- KG 节点**无页码字段**（list_kg_nodes 只回 node_id/name/type/chapter/section），无现成直接映射。
- **方案 B（有证据章节，优先）**：该章 evidence 节点的 `chat_id → chat_history.page_number`，直接精确落页，零新代码。
- **方案 A（无证据章节）**：节首扫描接口，契约如下——

**`GET /api/textbook/section-page`（新增只读接口）**

| 项 | 契约 |
|---|---|
| 请求 | `?textbook_id=…&section=3.1`（section 传**规范化前缀**如 "3.1"，由前端从 nodes 接口 section 字段剥离标题文字得到；不带 LaTeX/标题噪声） |
| 认证与校验 | 需登录（Bearer JWT，与 learning-map 一致）；`textbook_id` 使用后端 `app.textbooks.TEXTBOOK_LABELS` 校验，未知教材返回 400；`section` 只接受数字前缀（如 `3.1`） |
| 返回 200 | `{ page: 142, confidence: 0.92, matched_text: "3.1 n 维向量空间" }` |
| 扫描逻辑 | 后端复用教材资源层的逐页文本，找 `section` 前缀首次出现的页；精确前缀命中 confidence=1.0，去空白/LaTeX 噪声后的模糊命中 confidence=0.7–0.9。前端用一个 `normalizeSectionKey` helper 从 KG 的 section 文本提取数字前缀后再请求 |
| 缓存 | 进程内 LRU（key=textbook_id+section）；**接受多 worker 各自扫描**——结果确定性，重复扫描只浪费一次 CPU，不做跨进程共享 |
| 失败/超时 | 扫描 3s 超时或零命中 → 返回 `{ page: null, confidence: 0 }`；前端 fallback 到章序插值（仅保证不白屏，**不承诺页码精度**），再不行落第 1 页 |
| 验收 | **扫描成功时**：4 本教材每本抽 3 章人工比对，返回页码与 PDF 目录标注的章节起始页误差 ≤3 页；**扫描失败时**：只验收"不白屏、可继续进入阅读模式"，插值兜底不在精度保证范围内 |

- 入口分工（2026-08-18 实现定稿）：**继续学习卡 / 需巩固条目**带具体节点，优先用 B 精确落到来源页；**章节卡**是章节首页语义，直接用 A 扫描该章第一个 section；B 找不到记录时也退回 A；A 失败按上表 fallback。
- **行为更新（2026-08-18 合并计划，取代上文的"章节卡直接落地"）**：章节卡点击不再直接进 PDF，改为进入地图模式内的**章节详情**（分节+节点列表）；详情页「开始本章」按钮沿用本节的 A/B 落页逻辑进 PDF。继续学习卡 / 需巩固条目保留直进来源页的短路径。详见 FRONTEND_REDESIGN_EXECUTION_PLAN.md §4.2。

### 2.3 阅读模式：右栏改为「本页旁批」

**侧栏改为覆盖式 Drawer（已定，替代常驻左栏）**：
- 提问记录 + 学习地图不再常驻左侧 260px，改为从 **PDF 上方 toolbar** 的入口按钮打开的**覆盖式 drawer**（左侧滑出，遮罩点击关闭，不占布局宽度）。
- 理由：省下的 260px 全归 PDF；提问记录/地图是低频导航功能，不值得常驻占地；桌面/移动**同一套 drawer 交互**，心智模型统一，删一套桌面布局代码。
- PDF 上方新增常驻 toolbar：页码/翻页、缩放、`☰ 记录`、`🗺 地图`、`✂ 框选提问`——把现在散落的控件（header 框选按钮、PDFViewer 内嵌控件、移动端把手栏候选）收编成一处。
- LearningSidebar 组件原样复用，仅容器从常驻面板换成 drawer。

**断点分级（回应空间问题）**：右栏是唯一常驻面板，宽度随屏宽分级。

| 屏幕宽度 | 侧栏 | 右栏（旁批） | PDF 可用宽度 |
|---|---|---|---|
| ≥1440px | drawer（覆盖） | 常驻 400px | ~1040px |
| 1024–1440px | drawer（覆盖） | 常驻 360px，可手动收起 | ~860px |
| <1024px | drawer（覆盖） | 底部抽屉（见 2.5） | 全宽 |

用户手动折叠偏好存 localStorage 记忆。

**右栏是两态状态机，状态切换由用户驱动、不由页码驱动**（修正原"切页即切上下文"的硬伤：对话进行中翻到下一页看例题，面板不能被抽走）：

- **本页视图**（默认态）：当前页的对话卡列表。仅当处于此状态时，翻页才刷新右栏内容。
- **对话视图**：点卡片或发起新提问进入，显示激活线程。**进入后翻页不打断**——面板跟线程走，不跟页码走。
- 线程页码 ≠ 当前页码时，面板顶部出横幅「对话来自第 142 页 · 点击跳回」。
- 点「← 返回本页」退出对话视图，回到本页视图。

```
┌────────────────────────┬─────────────────┐
│ toolbar: ☰记录 🗺地图   │ 本页视图:        │
│  ◀ 142/421 ▶  ⊕⊖  ✂   │ 第142页 · 3 条   │
├────────────────────────┤ ┌─────────────┐ │
│                        │ │ Q: 线性无关… │ │
│      [PDF 页面]         │ └─────────────┘ │
│                        │ ┌─────────────┐ │
│          ● 徽标         │ │ Q: 秩的性质… │ │
│                        │ └─────────────┘ │
│                        │ [就此页提问…  ➤] │
└────────────────────────┴─────────────────┘
   侧栏为覆盖式 drawer，从 toolbar ☰/🗺 打开
```

- 数据：现有 `useQuestionList` 已拉全量记录，按 `page_number === currentPage` 过滤即可，无新 API
- 本页视图的输入框发新问题时**新建线程**挂到当前页（不再继承上一页的 activeThreadId）
- 追问：点对话卡进入对话视图，输入框变为对它的 follow_up（现有 follow_up 机制不变）
- 跨页/全局入口：侧栏 drawer「全部记录」视图保留现有 QuestionListPanel，搜索/跳转能力不丢

**D3（已定）**：当前页 0 条记录时，右栏显示**当前页上下文 + 2~3 个 starter prompt**（如「这页哪里没看懂？」「帮我讲讲本页的核心概念」），输入框始终固定底部；**不展示其他页的最近对话**——空态语义是"这一页还没有提问"，而非"推荐你回顾别处"。

### 2.4 提问动作原地完成（框选浮层）

现在：框选 → 截图飞进聊天面板待发区 → 打字 → 发送，视线离开书本两次。

改为：框选完成 → **选区旁浮出对话气泡**（内嵌输入框 + 流式回答），回答完毕关闭浮层时自动落成页面徽标 + 写入本页旁批列表。

**浮层只管第一问的「出生」，追问接力给面板**（回应"浮层里追问不方便"的问题）：

- 浮层闭环 = 框选 → 输入 → 流式回答。回答下方留「追问…」小输入框，轻量追问可直接来一轮（同一发送管道，成本很低）
- 浮层提供「在右栏展开」：对话要认真讨论时一键转为右栏激活线程，之后都在 400px 面板里进行
- **多轮截图分工**：第一图 = 选区本身；追加截图走老路（再次框选 → 进右栏 pendingImages 待发区，随下次追问发出）。浮层永远单图，不做多图管理
- 浮层是入口，面板是工作台，两者接力而非替代

       [PDF 页面]
    ┌────────────────┐
    │   ┌──────┐     │
    │   │ 选区  │─────┼──┐
    │   └──────┘     │  │  ╭──────────────╮
    │                │  └──│ 截图缩略       │

    │                │     │      [发送 ➤] │
    │                │     ╰──────────────╯
    └────────────────┘
```

- 纯文字提问仍走右栏输入框（无选区可依附）

**CaptureBubble 坐标协议（回应"不够具体"）**：

数据链上下游的坐标全是**页面比例**（0–1，相对当前页），只在渲染时换算一次像素：

| 环节 | 坐标形式 | 说明 |
|---|---|---|
| ScreenCapture 产出 | `cropBBox {x,y,w,h, unit:'page_ratio'}` | 已有协议，不动 |
| 浮层定位输入 | 同上 cropBBox | 浮层 = PDF 页容器内 `position:absolute`，`left/top` 由 cropBBox 换算 |
| 徽标落库 | `marker_y_ratio`（选区中心 Y）+ crop_bbox | 现有字段，不动 |

定位规则：
- 锚点：`anchorX = (bbox.x + bbox.width) × 页宽 + 8px`，`anchorY = bbox.y × 页高`（贴选区右侧）
- **碰撞翻转**：`anchorX + 浮层宽 > 页宽` → 翻到选区左侧；左右都放不下 → 放到选区下方；下方也不够 → 上方
- 浮层是 PDF 页容器的**子元素**，翻页时随页卸载自然消失；缩放时按页比例自动跟随（比例坐标 × 新页宽）
- **拖拽**：浮层可拖，位置存**比例**（相对页容器），翻转只是初始默认位
- **流式自适应**：内容 max-height 封顶（~60dvh），内部滚动，浮层框不随流式增长
- 移动端：选区太小/屏太窄时浮层退化为**从底部滑上的卡片**（不做页内定位），同一份内容组件换容器

**CaptureBubble 关闭规则（三态）与持久化时机**：

持久化时机锚在**回答完成**，不在浮层关闭——防止"回答完没关浮层就刷新页面"丢记录：

- **SSE 成功完成** → 立即创建/更新聊天记录和 marker（落库）；此刻数据已安全
- **浮层关闭** → 只负责隐藏 UI，不触发任何写操作
- **未发送草稿关闭** → 取消，不落库、不建 marker
- **流式回答中** → 禁止关闭（点击外部/Esc 无效，关闭按钮置灰 + 提示"回答中…"）

| 浮层状态 | 点击外部 / Esc | 数据结果 |
|---|---|---|
| 未发送 | 关闭 = 取消 | 无任何写入 |
| 流式中 | 禁止关闭 | 等待完成 |
| 回答完成 | 关闭 = 隐藏 UI | 数据已在完成时落库，关闭只是展示态 |

### 2.5 移动端：底部抽屉取代悬浮球

│             │

**占地对比（回应"方便阅读嘛"）**：

- AiBall 球：56px 圆形**悬浮遮挡**——停在哪盖哪，才有拖拽定位那套状态
- 把手栏：**44px 高（+ iOS 底部安全区），在布局流里、不在内容上**——PDF 视口永久让出这一条，内容永不被遮挡
- 把手栏**收编现有移动端控件**：页码/翻页、✂框选、AI、侧栏入口都进栏，现在悬浮的翻页按钮组撤掉，净占地反而下降

- 删 AiBall：去掉拖拽定位、屏幕尺寸监听那整套状态
- 展开形态：半屏 ~55vh 复用 ChatPanel（compact），全屏复用 LearningSidebar——组件不变，容器换
- 手势只绑在把手栏上触发，不与 PDF 翻页滑动冲突
- 有未读显示红点，有 pendingImages 显示截图数

**全局 overlay 层级（已定）**——任一时刻只允许一个 modal surface，桌面与移动共用同一套优先级：

```
CaptureBubble  >  UtilityDrawer  >  普通页面内容
（移动端在 UtilityDrawer 之下另有 BottomSheet 半屏/全屏档）
```

- 打开上层 → 自动收起所有下层（抽屉展开时触发框选 → 抽屉收回，浮层升起）
- 同层互斥：BottomSheet 半屏⇄全屏是同一层的两档不算重叠
- 桌面端同规则：UtilityDrawer 打开时框选 → drawer 收回；CaptureBubble 存在时打开 drawer → bubble 先收起
- 层级约束写进 App 顶层一个 `overlaySurface` 状态机（桌面：`'none' | 'drawer' | 'bubble'`；移动扩展 `'sheet-half' | 'sheet-full'`），禁止各组件各自维护布尔——这是 AiBall 时代状态散乱的教训

## 五、验收标准（每期定义"完成"的客观判据）

### P1a（壳层）
1. 宽屏（≥1440）与中屏（1280×800）下：无常驻左栏，PDF 区域比现状增宽 ≥200px
2. toolbar ☰/🗺 点击 → drawer 左滑出；遮罩点击/Esc 关闭；drawer 内提问记录与学习地图功能与现状一致
3. 页码/翻页/缩放/框选全部从 toolbar 可用，原入口（header 框选按钮、PDFViewer 内嵌控件）移除且无功能回退
4. 新令牌生效：主色 indigo、背景 #f6f7fb；**品牌主色不再使用 blue-***（状态色与公式编辑器等局部语义色允许保留明确蓝色，判定以截图+令牌为准，不做 class 名机械扫描）
5. 暗色模式切换正常，无未适配硬编码色
6. `vite build` 零 error；现有提问-回答-落库-回看主链路人工回归通过

### P1b（首屏）
1. 清 localStorage 首访 → 进地图模式；有证据用户再访 → 恢复上次教材+页码的阅读模式
2. 地图模式渲染：继续学习卡（无证据时显示引导）、章节网格（数据与 `/api/learning-map/chapters` 一致）、需巩固列表
3. 章节卡点击 → 阅读模式 + 落地页（有证据=来源页；无证据且扫描命中时，节首页与目录标注误差 ≤3 页；扫描未命中时仍可进入阅读模式，不把插值页当作精度承诺）
4. 地图⇄阅读切换不丢对话状态；教材切换时地图内容随之刷新
5. 移动端（375×812）地图模式可用：卡片单列、可滚动、点卡进阅读模式

### P1c（移动端）
1. AiBall 相关代码/状态全删；底部把手栏常驻 44px，不遮挡 PDF 内容（布局流内占位）
2. 把手上拉 → 半屏（本页旁批）；再上拉 → 全屏（记录+地图）；下拉逐级收回；手势不与 PDF 翻页滑动冲突
3. 未读红点、pendingImages 计数在把手栏正确显示；截图后抽屉自动升到半屏
4. 横屏（812×375）布局不破坏

### P2（锚定）
1. 本页视图：翻页后右栏立即显示 loading 态；正常网络下 **1 秒内**展示新页数据；**旧页数据不得以新页名义显示**（宁可 skeleton 不可错配）；请求失败显示明确错误 + 重试入口，不静默留旧数据。0 条页显示空态（D3 定案）+ 常驻输入框
2. 对话视图：进入线程后翻页，右栏内容不变，顶部出跨页横幅；点横幅跳回线程页码
3. 本页视图发送 → 新线程挂当前页（chat_history.page_number 正确）；对话视图发送 → follow_up 追加
4. evidence 自报链路不受影响：新线程/追问后 learning-map 节点证据正常落库（report_turn_outcome 走通）
5. 跨教材记录跳转（savePage/setTextbookId 时序）行为与现状一致

### P3（原地提问+视觉收尾）
1. 框选完成 → 浮层出现在选区旁（右侧优先，碰撞翻转规则生效）；输入发送 → 浮层内流式渲染
2. 浮层内追问一轮成功；「在右栏展开」后线程在右栏继续，历史不丢
3. 关闭浮层 → 页面徽标出现 + 本页旁批列表含该对话；追加截图（再次框选）进右栏 pendingImages
4. 缩放/翻页时浮层跟随/卸载行为符合坐标协议；移动端浮层退化为底部卡
5. 存量子组件视觉收尾完成：品牌主色全部收敛到 indigo 令牌（气泡/按钮/聚焦环/Logo）；状态色与局部语义色允许保留；暗色模式全界面走查通过。验收以截图 + 令牌审计为准
