# Qwen 与 Kimi 2.7 Code 六组对照实验记录

日期：2026-08-25  
环境：LearnMath 当前工作区，使用同一 OpenAI-compatible API，不修改生产配置

## 1. 实验目的

比较 `qwen3.8-max` 与 `kimi-k2.7-code` 在 LearnMath 目标场景中的：

- 数学文字回答正确性与解释质量；
- 数学图片识别与公式转写质量；
- 同一输入下的响应时间差异。

用户所说的 `kimi2.7-code` 在当前 API 中的可用规范 ID 为 `kimi-k2.7-code`；另有 `kimi/kimi-k2.7-code` 别名。

## 2. 固定条件

- 六个任务逐一发送给两个模型，问题文本和图片字节完全相同；
- `stream=false`，`max_tokens=1400`，`temperature=1`；
- 请求携带 `extra_body={"enable_thinking": false}`，用于隔离答案和视觉能力，不把长思考时间混入内容比较；
- 不提供 KG、学习记忆或动画工具；不写 `evidence_turns`、聊天记录、学生模型或 Redis；
- 使用固定中文数学教学系统提示词；
- 图片任务使用现有测试素材：清晰手写、手机拍摄手写、教材公式页。

注意：`kimi-k2.7-code` 的返回中仍出现了 `reasoning_content`，说明该模型/服务端没有完全遵守 `enable_thinking=false`。因此本记录的时间是请求完成时间，不把“思考已关闭”视为已验证事实。

| T2 | 导数为 0 不必为极值 | 18.993s | 14.688s | 两者均给出 `x^3` 反例；Kimi 更收敛，Qwen 有少量泛化性表述 |

六组中 Kimi 在 5 组更快，Qwen 仅在清晰手写识别 I1 更快。

## 4. 内容检查

### 文字任务

- T1：两者都得到根 `2、3`，并正确使用韦达定理解释根和为 `5`。
- T2：两者都使用 `f(x)=x^3` 说明 `f'(0)=0` 但不是极值，并给出一阶导数变号和二阶导数判别。Qwen 的回答更长，提到“通常对应拐点”时需要结合上下文，不能当作普遍定理；Kimi 的表述更谨慎。
- T3：两者都从 `AA^{-1}=I`、行列式乘法和 `det(I)=1` 推出结论。Qwen 额外逐项列出前置知识，Kimi 证明更短但逻辑闭合。

### 图片任务

- I1：两者都识别出 `x_1-x_2+x_0=0`、态矢量展开式和 `J_i` 求和式。两者都注意到 `F` 上方标记可能是横线或波浪线；Qwen 对可能的物理公式做了较多推测，Kimi 明确建议结合上下文确认。
- I2：手机透视图没有造成明显漏识别。Qwen 将第三式解释为输运/线性响应形式，Kimi 保留“看起来像”并标记下标存在不确定性。两者都没有声称看到了图片外的信息。
- I3：两者都正确识别“定积分与极限”、高斯积分、`(1+1/n)^n` 极限、`2x2` 矩阵以及“分别计算并说明推导过程”。Kimi 直接给出规范矩阵 LaTeX，Qwen 解释更长。

## 5. 结论

在关闭主观长思考、且不接入工具的内容对照中，没有发现 Kimi 2.7 Code 在图片识别或数学回答上明显弱于 Qwen 的断层。当前差异主要是：

- Kimi：通常更短、更快、对模糊符号更愿意标注不确定；
- Qwen：通常解释更完整，但更容易把图片公式扩展到未经确认的物理语境，回答也更长。

这组实验支持把 Kimi 2.7 Code 作为“低延迟文字/图片回答候选”，但不能直接证明它适合替换生产 Agent。

## 6. 未覆盖范围与后续门槛

本次没有验证：

- KG 查询和教材范围隔离；
- learner-memory index/detail 及当前轮可见性；
- evidence fork、阶段 3 replay 和 SSE；
- `render_manim_animation` 工具调用、Manim 代码质量和渲染成功率；
- 生产流式模式下的真实 thinking 延迟。

因此尚未修改 `QA_LLM_MODEL`，也没有重建或重启生产容器。正式切换前还需要用同一题集跑一次完整 Agent A/B：工具调用、学习记录读取、动画入队、回答完成和失败回退必须分别记录。
