# LearnMath 当前项目路线图

> 版本：v0.5
> 更新日期：2026-08-25
> 状态：当前有效

## 项目目标

LearnMath 要验证：以教材知识图谱为核心的 AI 教学 Agent，是否能比普通直接问答更准确地定位学生的知识缺口，并围绕缺失知识进行针对性教学。在验证成立的基础上，再扩展学习地图、学生模型和个性化练习。

## 阶段状态

### 阶段 1：KG 定位与针对性教学

状态：**已完成**。

已具备统一文字/图片问答、KG 节点定位、前置/后置及支撑关系检索、多轮脚手架教学、历史恢复和工具活动展示。当前可以证明“KG 已参与教学流程”，但尚不能仅凭功能完成证明“KG 教学效果优于无 KG 问答”。

### 阶段 2：学习地图

状态：**功能实现完成，业务有效性部分通过**。

已具备证据账本、确定性状态投影、静态教材目录、稀疏用户进度、章节地图、梯子关系图和问答后的增量更新。

未闭合事项：

- 真实学生测试出现“学生已完整作答，但后续轮次未产生闭合证据”；
- 尚未完成足量人工标注与模型投影的一致性验证；
- 旧 `/api/learning-map/*` 接口仍处于兼容保留状态，尚未形成明确下线记录。

因此，现阶段不能把地图颜色称为正式掌握度，也不能以单次 Agent 自评作为学生能力结论。

### 阶段 3：学生学习建模

状态：**节点级生产能力已实现，默认启用；扩展业务验收持续进行**。

当前已实现：

- 以 `evidence_turns` 为唯一事实源的 outcome adapter 和 Beta replay；
- 节点级 `unknown / emerging / likely_ready / model_needs_review` 状态、不确定性和 14 天时间衰减；
- 只读 `/api/learner-model` 接口；
- memory-first Agent 工具 `retrieve_learning_memory_index` 和 `retrieve_learning_memory_detail`；
- 当前轮 scope、用户/教材/节点隔离和脱敏的 learning-memory 状态活动；`AgentActivity.tsx` 已将查询中的运行、成功、部分可用和失败状态用中性文案呈现，内部模型参数仍不对学生公开。

当前实现边界：模型估计从 evidence 读时重算，`learner_node_estimates` 和 `learner_model_runs` 仅保留兼容表结构，不作为当前写入快照；`LEARNER_MODEL_ENABLED=true` 为默认值，阶段 3 节点级模型和 memory-first Agent 已进入生产。真实学生证据闭合、真实 LLM 链路和干净设备部署仍需持续验收，但不再是默认启用的前置条件。完整学生画像、反馈接口、自动出题和 Bloom/SOLO 等高阶诊断不在本阶段。

### 阶段 4：题目选择与生成

状态：**未开始**。

阶段 4 依赖阶段 3 的可解释模型和可验证使用规则。自动出题前还需要题目质量、难度、答案正确性、知识点覆盖和安全回退的验收机制。

## 次要流程

| 能力 | 当前状态 |
|---|---|
| AI 原生答题与 KG 定位 | 已实现 |
| 提问记录和页面笔记组织 | 已实现基础记录与恢复 |
| 错题/笔记 PDF 导出 | 未实现 |
| 桌面、平板和移动适配 | 已实现并有视觉/E2E 验收记录 |
| Windows Docker 一键部署 | 脚本与离线包构建链路已实现；仍需干净设备最终验收 |

### Manim 动画能力

状态：**二维能力已实现，三维暂未开放**。

当前 Manim 链路已经完成模型生成、Redis 排队、断网 Renderer、视频/海报回传和前端播放；复杂二维函数（包括处处连续但处处不可导函数的有限项近似）可以生成。当前策略要求唯一的 `GeneratedScene(Scene)`，因此不接受标准 `ThreeDScene` 和真实三维相机动画。这个边界是出于模型生成 Python 的安全、资源和可复现性约束，不是 Manim 引擎能力缺失。

三维能力的后续入口、风险和验收条件统一记录在 [Manim 能力边界与演进方向](../07-decisions/MANIM_SCOPE_AND_SECURITY.md)。在完成受控三维场景白名单、资源预算、无 GPU 回归测试和视觉非空检查前，不把三维标记为已支持。

## 当前优先级

1. 复验并修复阶段 2 的闭合证据可靠性。
2. 持续完成阶段 3 的 P0 回放、隔离、memory 工具边界和真实学生链路验收；生产开关已默认开启，验收结果用于质量监控和后续迭代。
3. 建立 KG 开启/关闭的对照评价，直接回答“KG 是否有用”。
4. 补做干净 Windows 设备的一键部署验收。
5. 单独规划错题/笔记打印与 PDF 导出。
6. 保持二维 Manim golden cases 和 Renderer 资源基线；三维按独立能力包评审，不通过删除现有策略检查的方式放开。

阶段 4 仍应等待阶段 2 证据闭合并形成稳定输入后再启动；阶段 3 默认启用不等于自动出题所需的题库、难度和质量验收已经完成。
