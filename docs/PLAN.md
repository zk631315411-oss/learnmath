# LearnMath 项目计划

> 项目：学数有道（LearnMath）
> 版本：v0.3
> 更新日期：2026-08-14
> 状态：现实版优先；理想版仅作未来参考

## 0. 项目目标

LearnMath 要验证：以教材知识图谱（KG）为核心的 AI 教学 Agent，能否比普通直接问答更准确地定位学生的知识缺口，并围绕缺失知识进行针对性教学。

完整路线分四个阶段：

1. KG 定位与针对性教学：让学生看到目标知识的前置和后置，并围绕最相关缺口展开教学。
2. 学习地图：让学生看到哪些知识学得较好、哪些仍需学习。
3. 学习建模：依据 KG 节点积累学习证据，形成可解释的学习情况模型。
4. 题目推荐与生成：根据知识路径和学生情况选择或生成适合的题目。

当前只实施阶段 1。学习画像、正式掌握度、考试评分、防作弊、教师审核和自动出题均不属于当前验收范围。

## 1. 双轨架构决策

### 1.1 现实版：当前唯一实施主线

现实版采用单一多模态 Kimi Agent 和 Prompt 驱动的软教学流程：

```text
文字问题 / 截图问题
-> QATurnInput
-> 单一多模态 ToolRuntime
-> Kimi 按需调用 retrieve_kg_context
-> 定位目标知识及有界的前置/后置/支撑/应用路径
-> 询问学生当前思路
-> Kimi 结合最近对话临时判断教学阶段和回答质量
-> 提问、分级提示、直接教学或继续验证
-> SSE 展示思考、工具活动和答案
-> 保存原始对话、工具活动与可展示知识路径
```

现实版不要求 Kimi 输出结构化 SOLO、Bloom 或 `next_action`，不增加第二个评估模型，不实现 Python 教学控制器，也不持久化掌握度或证据账本。

### 1.2 理想版：未来演进参考

理想版可在现实版暴露出稳定问题后增加：

- 结构化回答评估；
- 显式教学状态机与迁移校验；
- Bloom、SOLO、脚手架级别和知识缺口状态；
- 证据账本、学习画像与跨会话状态恢复；
- 受控的平行验证、迁移题和长期路径规划。

这些能力当前暂不实现，也不得成为阶段 1 的验收条件。

## 2. 阶段 1 教学闭环

### 2.1 用户流程

1. 学生输入文字问题或上传题目截图。
2. Kimi 识别题目与目标知识点，并在需要教材结构时调用 KG。
3. 界面展示本轮 KG 查询、目标节点以及有结果的前置或后置路径。
4. 若学生尚未给出尝试，Kimi 先询问当前思路；若已有完整尝试，直接从尝试中的关键步骤开始判断。
5. Kimi 一次只提出一个可观察问题，从必要基础逐步走向理解、应用和分析。
6. 学生答不上来时，依次使用一般性推动、具体线索、针对性脚手架；仍不会则直接教学。
7. 直接教学后继续给一个平行验证问题，不把给出答案当作教学结束。
8. 学生明确结束时给出简短小结。

不规定固定教学题数，也不要求每个案例恰好追问 3 轮。是否继续由 Kimi 根据学生反应判断；`ToolRuntime` 的模型轮数、工具请求数和超时只用于基础设施保护。

### 2.2 软判断规则

- Bloom 只用于逐步增加任务复杂度，不显示给学生，也不持久化。
- SOLO 只作为回答结构质量的临时启发，不等同于数学正确性，不显示也不持久化。
- 每轮结合原始对话推断当前阶段；现实版允许出现偶尔重复或跳步，并通过场景回归约束 Prompt。
- 学生明确要求直接讲解时立即讲解，不强迫完成提示序列；之后仍可给一个验证问题。
- 当前只能宣称“KG 辅助定位与针对性教学”，不能宣称已经正式诊断或证明学生掌握。

## 3. 当前技术架构

```text
D:\LearnMath\
|- app/
|  |- routers/qa.py                         # 文字/截图统一 SSE 入口
|  |- services/qa/answer_service.py         # 单一 Agent 编排与流式输出
|  |- services/qa/prompt_builder.py         # 现实版软教学规则
|  |- services/agents/tool_runtime.py       # 有界工具循环
|  |- services/agents/tools/
|  |  `- retrieve_kg_context.py             # KG 工具契约
|  `- db/kg_v44.py                          # Neo4j 只读定位与定向展开
|- frontend/src/                            # React / Vite / SSE 界面
|- docs/KG_TOOL_DESIGN.md                   # KG 工具 v0.6 设计与实际契约
|- docs/PLAN.md                             # 本计划
`- tests/                                   # Agent、KG、SSE 回归
```

不新建独立 `src/`、`web/` 或 JSON KG 工程，不以 BM25 替换现有 Neo4j。

## 4. 技术决策

### 4.1 KG

- 使用现有本地 Neo4j；Aura 替换后运行相同回归。
- 所有查询只读，不修改节点、关系、属性、Schema、索引或约束。
- Kimi 通过 `retrieve_kg_context(query, node_id?, focus?)` 按需查询。
- 节点定位、消歧、关系方向、RuleCase 和返回上限以 `docs/KG_TOOL_DESIGN.md` v0.6 为准。
- 严格前置/后置与普通支撑/应用分开，空结果不由其他关系冒充。
- 只展示有界知识路径，不做无界多跳子图展开。

### 4.2 Agent 与 Prompt

- 文字和截图共享同一个多模态 `ToolRuntime`；图片只是 user message 的内容类型。
- Kimi 自主决定是否调用 KG，并按教学目的选择 `focus`。
- 系统 Prompt 提供软阶段、回答质量启发和四级脚手架规则。
- 最近原始对话和本轮真实问题必须传给模型；不能用默认截图文案覆盖用户输入。
- 生产运行时最多 5 次可选择工具的模型调用、最多 3 次工具请求，并保留去重、超时和强制收尾。
- 供应商拒绝“图片 + tools”时明确报错，不降级到无 KG 的截图直答。

### 4.3 前端与持久化

- 使用 React、Vite 和现有 SSE 协议。
- 展示 `thinking`、`content`、`tool_call`、`tool_result`、`done` 和 `error`。
- KG 工具活动展示目标、请求方向、明确前置、明确后置、空方向和截断状态。
- 一个页面徽标代表一段现实版连续对话；普通追问追加到该徽标的原始 `follow_ups`。
- 刷新或重新打开徽标时恢复原始问答、思考内容和工具活动。
- 当前不实现标准化对话树、教学状态快照或跨会话显式状态恢复。
- 界面不显示“已掌握/待复习”等未经正式证据支持的颜色或结论。

## 5. 从 ai-math 复用什么

当前现实版复用：

- 苏格拉底式教学 Prompt 经验；
- Bloom、SOLO 和最少提示系统的行为规则；
- Neo4j 只读查询与关系语义经验；
- 原始追问历史、截图上下文和前端流式交互方式。

仅作为理想版未来参考：

- `scaffolding_controller` 一类显式控制器；
- 结构化评估与显式状态机；
- 证据缓冲、掌握度、学习画像和对话树。

不迁移旧 JSON/BM25 主架构、独立 `src/`/`web/` 目录、考试业务或无关模块。

## 6. 当前实施里程碑

1. 确认文字和截图统一进入多模态 Agent 工具链。
2. 修复 Prompt 组装，确保本轮问题、最近历史和截图上下文真正传给 Kimi。
3. 统一 Prompt 中的 KG 字段与 `retrieve_kg_context` 当前契约，并修正数学示例。
4. 默认使用苏格拉底式软教学流程，完成四级脚手架和教学后验证。
5. 在同一徽标中保存并恢复连续追问、思考过程和 KG 工具活动。
6. 用“特征值”“线性无关”等真实问题验证目标定位、前驱链和针对性教学。
7. 完成后端测试、Python 编译、前端构建和浏览器端到端演示。

## 7. 风险与缓解

| 风险 | 现实影响 | 当前缓解 |
|---|---|---|
| Kimi 跳过或重复教学阶段 | 提示顺序不稳定 | 固定软教学规则，用真实错题做多轮场景回归 |
| 没有结构化教学状态 | 刷新后只能靠原始历史推断 | 保存完整原始问答和工具轨迹；显式状态留给理想版 |
| KG 严格前置关系稀疏 | 前驱链可能为空 | 明确展示空方向；支撑关系单独返回，不冒充严格前置 |
| 模型未调用 KG | 无法证明本轮有 KG 参与 | 展示并保存工具活动；验收案例检查真实调用 |
| Prompt 判断不等于掌握证据 | 容易过度宣称效果 | 阶段 1 只验证定位与针对性教学，不宣称正式掌握度 |
| 图片和工具组合被供应商拒绝 | 截图问答失败 | 返回明确错误，不静默降级成无 KG 直答 |

## 8. 阶段 1 验收标准

阶段 1 完成需同时满足：

1. 文字和截图进入同一条多模态 Agent 与 KG 工具链。
2. 用户实际输入、截图和最近对话均正确到达模型；“为什么”等追问不会被默认图片文案替换。
3. 需要教材知识时 Kimi 能调用 KG，并能展示目标、明确前置、明确后置或其他真实检索方向。
4. 新问题首轮优先了解学生当前思路，已有尝试时不重复询问。
5. 多轮对话中能执行递进提示；必要时直接教学，并在教学后继续验证。
6. 不把支撑关系冒充严格前置，不把 `EQUATIVE` 解释为数学等价，不把截断结果说成完整集合。
7. 思考、答案和工具活动保持流式展示，用户阅读上方内容时不会被强制拉到底部。
8. 同一徽标的原始历史、思考内容和 KG 工具活动能保存并恢复。
9. “特征值”“线性无关”等真实案例可完成 KG 定位与针对性教学演示。
10. 后端测试、Python 编译、前端构建和桌面/移动端基础浏览器验收通过。

## 9. 明确不在当前阶段实现

- 独立评估模型或 `record_teaching_assessment` 内部工具；
- Python 显式教学状态控制器和迁移校验；
- SOLO、Bloom、提示级别、掌握度或证据账本持久化；
- 标准化对话树、显式分支和教学状态快照；
- 学习画像、学习地图正式评分、自动选题和生成题目；
- 考试评分、防作弊、教师审核和申诉；
- 修改 Neo4j 图数据、Schema 或索引。

## 10. 后续路线

现实版运行并积累真实场景后，再根据可观察问题决定是否进入理想版。只有当重复提问、错误升层、跨会话恢复或掌握度证据成为稳定需求时，才引入结构化评估、显式状态机和证据存储，避免在验证 KG 教学价值之前提前搭建复杂控制系统。
