## 1. 背景与目标

学数有道即将开放给同学内测。新用户首次访问时需要：
- 了解产品核心价值
- 知道如何登录（测试账号规则）
- 快速看到产品亮点（预置数据 + PV 视频）
- 有渠道反馈问题

## 2. 弹窗设计

### 2.1 触发逻辑

| 条件 | 行为 |
|------|------|
| 首次访问（无 localStorage 标记） | 自动弹出欢迎弹窗 |
| 勾选"不再显示"并关闭 | 写入 `localStorage: learnmath.welcome.dismissed = 1` |
| 已标记不再显示 | 不再自动弹出，但可通过入口手动打开（可选） |
| 清缓存/换浏览器 | 重置为未读状态，会再次弹出 |

## 5. PV 视频方案

| 方案 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 本地 `public/videos/pv.mp4` | 加载快、无外部依赖、可控 | 增加部署包体积 | **首选** |
| B 站 iframe | 不占服务器带宽、有弹幕 | 加载慢、可能有广告、样式不可控 | 备选 |
| 腾讯视频 iframe | 同上 | 同上 | 不考虑 |

**建议：** 先本地，视频压缩到 5MB 以内（720p + 低码率），后续流量大了再切 B 站。

## 6. 测试账号与模拟数据

### 6.1 账号规划

统一 `test_001` ~ `test_010`，密码 `123456`。先准备 1–2 个样板账号，使用真实问答链路形成**中等程度**学习数据：部分节点 mastered、部分 learning，让用户一眼看到学习地图的效果，同时保留探索空间。其余账号从样板账号复制数据，用于快速形成一致的内测初始状态。

复制必须按账号隔离执行：

- 为每个目标账号创建独立的 `user_id`；
- 复制 `chat_history` 和 `evidence_turns` 时重建 `chat_id`、`qa_turn_id`、`client_turn_id` 等账号/对话关联标识；
- 不复制或共享原账号的登录令牌、用户身份、截图缓存和 Manim 产物；
- 复制完成后按目标账号重新计算学习进度/学生模型，并确认 `/api/learning-progress` 的 revision 从目标账号自己的基线开始；
- 用两个不同账号互查教材、对话、证据和学习地图，确认没有跨账号可见数据。

### 6.2 模拟数据生成方式（已确认）

**方案 A：样板账号真实模拟 + 账号级复制**
- 先为 1–2 个样板账号调用 `/api/qa/solve-stream`，模拟学生提问和回答；
- 通过受控复制脚本把样板数据复制到其余内测账号，并重建所有账号/对话关联；
- 复制后只做必要的抽查问答，不再为每个账号完整消耗一遍 LLM 额度。
- 优点：真实走完整链路，数据可信，准备速度快、API 成本可控；
- 缺点：复制账号的学习轨迹相似，需要在后续内测中逐步产生差异化数据。

**已确认：**
- 使用 **方案 A：样板账号真实模拟 + 账号级复制**
- 学科范围：**只做高等代数上（gaodai_shang）**
- 10 个测试账号（test_001 ~ test_010）；其中 1–2 个先生成样板数据，其余账号从样板复制并完成隔离校验

## 9. 风险与注意事项

| 风险 | 缓解措施 |
|------|---------|
| 测试账号密码太简单，被滥用 | 内测阶段可控，正式版强制改密码 |
| 模拟数据影响真实用户统计 | 测试账号数据打标，统计时可过滤 |
| 本地 JSON 存储并发写入冲突 | 单文件锁或按日期分文件 |
| 视频文件过大影响加载 | 压缩 + 懒加载 + 提供"跳过视频"按钮 |
